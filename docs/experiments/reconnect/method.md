# 弱网恢复对照方法

## 问题与对照

比较同一访客通过身份恢复后，在 10 秒内能否重新获得正确且可继续操作的牌桌状态。两组均连接同一应用实现并执行 `session:resume`。快照组应用授权返回的房间和本人手牌快照。基线组保留断线前的视图，仅接受认证后由新业务触发的普通牌桌更新。差异只存在于测试观察端。

每次使用独立编译服务、临时 SQLite、回环端口、两名新访客和同一对照种子。双人桌由大盲探针在翻牌下注，待确认视图后切断代理。对手通过直连在网络恢复前约 3 秒跟注，服务端进入转牌且轮到探针。观察窗口内不人工触发新提交。探针恢复后，用原 ID 和载荷重发已提交动作，核对重复收据、当前版本和余额，再过牌验证后续动作。

## 条件与样本

| 条件 | 断网 | 延迟模型 |
|---|---:|---|
| offline5 | 5 秒 | 本机基线 |
| offline30 | 30 秒 | 本机基线 |
| rtt300_offline5 | 5 秒 | 双向各约 150ms，实测往返写入 CSV |

每条件 30 对，每对两组，共 180 次。种子为主种子加条件编号乘 1000 再加配对序号。奇数对先快照，偶数对先基线。同一对始终串行。正式运行启用六条独立配对执行通道，同条件成批执行。每条通道独享应用、代理和数据库，计时共享主机和 Node 进程。试跑单独保留六条记录。

## 判定与数据

- 恢复网络起计 10 秒。参与身份、服务器 epoch、房间、手号、版本、行动者、回合和余额与权威本人投影全部一致才记恢复。
- 超时或失败样本留在分母，恢复耗时留空。仅对恢复者发起重复扣款探针，表中明确记录探针分母。
- 恢复成功的耗时以中位数和最近秩 P95 表示。网络恢复前的实际离线时长和每次实测 RTT 各自保存。
- 排程失效、代理或服务初始化异常单独记入失效日志。同条件同种子至多尝试三次。应用级恢复失败和状态不符直接进入正式样本。
- 原始 CSV 只含公开实验参数、耗时、版本号及结果。报告基于固定对手时序和 10 秒观察窗口，不外推到公网时延、长时断线或其他恢复算法。

## 重跑

```sh
npm run build
npm run test:integration -- tests/integration/reconnect-experiment.test.ts
npm run experiment:reconnect -- --pairs 1 --seed 20261106 --output docs/experiments/reconnect/new-pilot.csv
npm run experiment:reconnect -- --pairs 30 --lanes 6 --seed 20261106 --output docs/experiments/reconnect/new-run.csv
npm run experiment:reconnect -- --summarize docs/experiments/reconnect/new-run.csv
```

串行复跑可省略 `--lanes`。输出路径必须是新文件。同名环境记录保存机器、版本、候选指纹与参数。若运行中断，`.partial` 只用于诊断，正式汇总以完整配对 CSV 为准。
