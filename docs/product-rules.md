# 轨道牌桌：首版产品规则

版本：1.0.0｜基线日期：2026-10-30｜对应任务：W01。

本文是后续客户端、服务端、规则引擎与验收共同遵循的产品基线。它描述目标行为，不表示应用已实现。边界决定见[decisions.md](decisions.md)，用户故事见[user-flows.md](user-flows.md)，具体输入与期望见[scenarios.json](../tests/fixtures/scenarios.json)。

## 1. 首版目标与范围

打开网页即可参加最多四座的无限注德州扑克，支持单人练习、好友联机与真人/电脑混合桌。所有筹码均为虚拟筹码。

首版包括：访客身份、创建/加入房间、准备、完整牌局、30秒行动计时、断线恢复、两种电脑难度、原创卡面、手机操作、已结束牌局的权限回放。

首版不包括：注册账号、跨设备账号找回、匹配大厅、独立观战、聊天、现金支付、升盲、跨桌比赛、多人服务器扩展、服务器重启续打和实时好友桌策略建议。

## 2. 模式与人数

| 类别 | 真人 | 电脑 | 总人数 | 开局条件 |
|---|---:|---:|---:|---|
| 单人练习，对战1个电脑 | 1 | 1 | 2 | 真人在线并准备，房主开始 |
| 单人练习，对战2个电脑 | 1 | 2 | 3 | 真人在线并准备，房主开始 |
| 单人练习，对战3个电脑 | 1 | 3 | 4 | 真人在线并准备，房主开始 |
| 双人好友 | 2 | 0 | 2 | 两名参赛真人在线并准备，房主开始 |
| 三人好友 | 3 | 0 | 3 | 三名参赛真人在线并准备，房主开始 |
| 四人好友 | 4 | 0 | 4 | 四名参赛真人在线并准备，房主开始 |
| 混合桌 | 1—3 | 1—3 | 2—4 | 所有参赛真人在线并准备，房主开始 |

人数约束：

1. 容量可选2/3/4，默认4；容量是上限，不是最低开局人数。
2. 已有2人或3人且满足准备条件时，无需坐满四人即可开局。
3. 1真人+0电脑不能开始；空座不会自动加入电脑；达到容量后拒绝新入座。
4. 单人模式与好友桌复用相同规则；电脑免准备，不拥有房主权限。
5. 同一访客身份在同一房间只能占一个真人座位。
6. “对战3个电脑”表示自己加三个电脑，共四人，每位玩家独立竞争。

## 3. 默认参数

| 项目 | 固定值或行为 |
|---|---|
| 牌组 | 52张，S/H/C/D四花色，2—A十三牌值，无大小王 |
| 游戏 | 无限注德州扑克 |
| 初始筹码 | 每次新入座发2,000；手中加入者手间才发放 |
| 小盲/大盲 | 10/20，整场不升盲 |
| 行动期限 | 每个有效回合30秒，由服务器确定deadline |
| 超时 | 可过牌则过牌，否则弃牌；不自动跟注 |
| 保座 | 意外断线起120秒，不重置当前30秒期限 |
| 每手之间 | 展示结算，参赛真人重新准备，房主开始 |
| 电脑难度 | 入门、标准；风格电脑为后续增强 |
| 展示语言 | 中文，牌值使用A/K/Q/J/10—2 |
| 访客凭据 | 建议有效30天；与120秒保座分离 |

## 4. 房间、场、手与身份

- **房间Room：**邀请、成员、容量、房主和准备的容器，允许进行多场。
- **场Match：**从统一初始状态开始，到场结束或重开；包含多手牌。
- **手Hand：**一次发牌到一次结算，参赛名单开始时冻结。
- **逻辑座位seatId：**0—3固定编号，用于顺时针排序；显示位置可以旋转。
- **入座身份participantId：**一次入座到离开，可跨同房间重开；离开再入生成新身份。
- **访客sessionId：**用于恢复和回放权限，不能用socket.id或房间码代替。

入座状态分为waitingNextHand、active、eliminated、leaving。等待发筹码者显示“下一手加入”，不能因为当前筹码为0就显示出局。

## 5. 开局与手间管理

### 5.1 开局资格

必须同时满足：

1. 房间处于等待或手间，上一手已结算，当前无存储故障。
2. 已完成手间加入/退出处理，有2—capacity个筹码大于0的active座位。
3. 所有有资格参赛的真人在线并准备完成；有筹码的离线保座真人会阻止开下一手。
4. 房主在线并发起开始；非房主开始被拒绝。
5. 没有尚未处理完的重新开场提议。

服务器返回可开局与阻止原因，界面同时展示“当前人数/容量”和准备条件。筹码为0的出局真人不阻止正常下一手，但新场重置需要其同意。

### 5.2 手间变更

- 添加/移除电脑、调整容量、重开只在手间执行。
- 成员、电脑、容量变化清空真人准备状态；只有实际变更才触发，重复命令不重复清空。
- 降容量不得小于已占座数；不重新编号已占座的seatId。
- 电脑不能被真人在手中直接替换；其底牌、筹码和入座身份不转交。
- 新增座位、移除座位、重置筹码均写台账。

### 5.3 中途加入

空座允许真人加入并立即占用容量，但不能加入本手冻结名单。加入者只看入座后的公开快照与后续公开动作；不补发入座前事件流，不获取本手私人回放。

手间给该座位发2,000并记录seat_grant，转为active，重置准备。发放前退出不产生虚构的增发和退出记录。

## 6. 牌、发牌与判胜

### 6.1 牌编号和洗牌

逻辑编号如AS、10H、QC、KD；牌组规范顺序为S/H/C/D各自2—A，实际对局必须先洗牌。素材映射不能改变逻辑牌值。

服务器使用密码学安全随机源和Fisher–Yates。固定牌序和测试种子仅用于测试，真实房间拒绝客户端指定牌序或随机种子。

### 6.2 发牌

- 每人两张底牌，逐人一张、重复两圈。
- 三至四人从小盲起顺时针发；双人每圈从大盲发到庄家。
- 翻牌烧1发3，转牌烧1发1，河牌烧1发1。
- 底牌、公共牌、烧牌和剩余牌不得重复；未发牌和烧牌不发客户端。
- 完整到河牌，2/3/4人分别消耗12/14/16张。

### 6.3 最佳五张

从5—7张中选择最佳五张；公共牌可以完全构成最佳牌，不要求使用底牌。牌型从低到高：高牌、对子、两对、三条、顺子、同花、葫芦、四条、同花顺。

皇家同花顺是A高同花顺，不单设第十类别。A2345为五高顺子。相同牌型按主牌和踢脚牌比较，花色不打破平局。

## 7. 位置与行动

- 三至四人：庄家后为小盲，再后为大盲；翻牌前从大盲后开始；翻牌后从庄家后的首位可行动者开始。
- 双人：庄家兼小盲，翻前先行动，翻后后行动；另一个人为大盲。
- 首手随机庄家；手间按存活座位轮转；多人转双人按R01调整，防止存活者连续大盲。
- 弃牌、全押、出局和未参赛座位跳过行动，但全押未弃牌者仍有合资格底池获胜权。
- 盲注筹码不足时只实扣剩余并全押，翻前下注标线仍20。
- 盲注不是自愿行动，无人加注时大盲仍有过牌/加注机会。

## 8. 金额与合法行动

### 8.1 统一口径

- stack：尚未投入的筹码。
- streetCommitted：本轮累计投入。
- handCommitted：本手累计投入，已包含本轮。
- currentBet：本轮需要达到的下注标线。
- callAmount：本次还需跟注的金额，由服务器给出。
- raiseTo：本轮累计加注至多少；追加额为raiseTo−streetCommitted。

所有金额为安全整数。例：本人本轮已投10，最低加注至40时追加30；不是再追加40。

### 8.2 动作

1. 只有actor可提交行动；非本人回合不能预提交动作。
2. 没有跟注差额才可过牌；弃牌允许在本回合执行。
3. 筹码足够时可普通跟注；筹码小于或等于差额时用全押跟注表达，不能扣成负数。
4. 翻后最低完整开注20；翻前20尚未加注时最低加注至40。
5. 完整加注后，下一次完整加注的增量至少等于上一完整增量。
6. 不足最低额的下注/加注只在投入全部剩余筹码时合法；普通非法raise不替玩家补额或改成全押。
7. 无其他仍有筹码且未弃牌的对手时不允许主动加注；仍欠差额时给跟注/弃牌选择，否则直接跑牌。
8. 负数、小数、字符串金额、NaN、Infinity、不安全整数及超额输入拒绝，状态不变。

### 8.3 短全押与重开权

短全押提高标线，不更新上一完整增量。每位玩家记录上次完成行动时面对的标线，累计新面对的增幅足够一次完整增量才重新获得加注权。

例：A下注100，B全押150，C跟150，D弃牌，A不能再加；若C改为全押200且D跟200后仍有筹码，回A时可最低加至300。若C先跟150、后来才面对200，C新面对只有50，不重开。若D弃牌而仅A还持有筹码，则即使累计增幅足够，也因无人可响应而禁止实际加注。

过牌也属于已行动。翻后A过牌、B短全押10时，尚未行动且仍有可响应对手的C可最低加至30；不能仅补至20。若C跟10、D弃，回A不能凭10短额重新加注。

全押仍受加注权约束，不能借allIn绕过限制。

## 9. 推进、边池与结算

### 9.1 推进

所有仍需行动者已回应当前标线且跟注差额已解决，才能结束本轮。翻前其他人补齐盲注后，大盲仍需完成选择；“全轮过牌”不是允许小盲免跟注。

只剩一位未弃牌者时直接结算，不必补公共牌或公开底牌。所有竞争者全押或仅一人有筹码且已无差额时，按正常烧发顺序补齐公共牌后结算。

### 9.2 返还和分池

先返还唯一未匹配的超额贡献，再按贡献高度分池。弃牌投入留在池中，但弃牌者无资格获胜。各池独立判胜、平分，余数给庄家左侧顺时针的该池并列赢家。

| 例子 | 结果 |
|---|---|
| A100/B250/C400/D400 | 池400、450、300，总1,150 |
| 同例D弃牌 | 金额不变；D失去资格，最后池仅C有资格 |
| A100/B250/C400 | C返还150；池300、300 |
| 三人各1，C弃牌，A/B平局，庄家C | A在庄家左侧先获余数：A2、B1 |

退款不是赢池。结果需分别展示各池分配、退款和最终筹码；重复推进已结束手不能再次派奖。

### 9.3 筹码守恒与台账

未结算时，所有stack+所有handCommitted等于本手初始总额；handCommitted已含streetCommitted，不能重复相加。派奖时同步清掉已分配贡献，避免双计。

手间事件使用seat_grant、seat_cashout、match_reset_remove、match_reset_grant。离开按最终剩余筹码登记移出；重开先登记移除旧余额，再给全座统一发2,000。场外增减不能混入单手守恒。

## 10. 超时、退出与房主

| 情况 | 处理 |
|---|---|
| 当前actor超时 | 能过牌则过牌，否则弃牌 |
| 意外断线 | 保座120秒，原30秒继续；恢复不撤销已执行超时 |
| 当前actor主动退出 | 未全押则弃牌，手间移除 |
| 非actor主动退出 | 标记leaving，轮到本人自动弃牌，手间移除 |
| 已全押退出 | 保留资格完成本手结算，再移除并记最终筹码 |
| 已弃牌退出 | 不再改变本手，手间移除 |
| 离线超120秒且手进行中 | 标记手间退出，保留已全押结算资格 |
| 手间退出或保座已到期 | 立即执行移除和台账 |
| 房主断线未到120秒 | 房主保留，当前手继续，手间不开新手 |
| 房主超过120秒 | 转给最早加入且在线的真人；无在线真人则等关闭 |
| 全真人离线 | 本手依超时结束；不再开新手，手结束且保座都到期后关闭 |

新连接通过凭据接管后旧连接失权。同一回合真人动作与到时竞争只应用一个有效结果。恢复、动画、全押确认不延长行动期限。

## 11. 场结束与重开

筹码归零者出局，留在结果界面。存活active座位不足两人则本场结束，房间可保留等待重开或新成员，但新手仍须满足开局条件。

房主手间提出重开，清空准备；全部入座真人在线并准备才表示同意，包括零筹码者。房主再次开始时创建新match，统一恢复2,000并登记台账。取消提议或成员变化清空同意。

## 12. 信息公开与回放

- 本人参赛底牌只发本人，其他玩家未公开牌仅发两张牌背数量。
- 只剩一人直接赢池不强制公开；有竞争的摊牌公开未弃牌者底牌，已弃牌牌不公开。
- 全押本身不立即亮牌，等所有下注决定完成后进入公开流程。
- 回放仅本人参赛手可访问；同房间等待过不等于参赛。
- 本人可回看本人底牌；对手只显示当时已公开的牌；隐藏牌不因牌局结束自动解除权限。
- 进行中手不开放完整回放；中止手标记interrupted，无最终派彩，不混入正常赢池统计。
- 电脑只能看本人底牌和公开信息；不能共享其他电脑底牌或读取真实未来牌。
- 断线恢复凭据和房间码分离；凭据丢失首版无法找回私人历史。

## 13. 故障边界

状态与收据持久化成功后才发布成功确认。同一命令重试只应用一次；旧手、旧回合、旧版本拒绝并同步最新本人视图。

持久化故障暂停房间，不继续扣筹码或发牌。首版故障恢复与进程重启均不承诺续打未完成手；保留已结束记录，未完成手记为interrupted，界面提示重开。
