## 3. 本轮落实的具体口径

1. 房间内业务请求显式带roomId作为定位，服务器仍核验成员身份；新增ROOM_FORBIDDEN避免给陌生房间返回状态。
2. 身份交换/只读查询带requestId，用私有返回通道；11个业务变更用commandId收据，二者不混用。
3. roomVersion覆盖RoomView实际变化，包括下注引起的公开筹码变化；expectedVersion始终只比handVersion，中途加入不误伤当前下注。
4. CommandSuccess增加受影响手的handId/appliedHandVersion成对可空字段，旧确认不用于覆盖最新快照。
5. 明确seatRestored、identityOnly、handInterrupted，身份有效与席位恢复分开。
6. 首次私有身份发行是允许返回令牌的例外；普通确认、状态、房间视图和回放均不返回令牌。
7. 回放只读状态剔除turnId/deadline和实时legalActions；中止手无结果和最终盈利。
8. 私有快照类型与公开房间/结算类型分开；错误使用允许字段，不导出异常或数据库实体。
9. 已认证控制身份先查询自己的最终收据，再对新命令检查当前房间归属；退出后丢确认重试仍可取原结果，但不能获得退出后的桌面。

这些是W01规则的通信表达和实现细化，没有改变筹码、人数、下注、退出或公开规则。

## 4. 证据的边界

当前环境没有项目TypeScript编译器和工程配置；按W02规划，本轮没有安装依赖、创建package.json、运行tsc/Vitest/Playwright或启动服务器。

资料校验器不是生产输入校验器。它对14个通信夹具做独立核对，不证明所有网络输入均可处理，也不证明TypeScript声明已经可编译。

机器报告明确记录typescriptCompiled=false、runtimeInputValidationImplemented=false、serverStarted=false、networkTestsRun=false。不把静态文本/JSON检查称为编译、运行时鉴权、网络测试或泄露测试已通过。
