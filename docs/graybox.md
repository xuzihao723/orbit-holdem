## 组件及数据责任

`dev/graybox-fixtures.ts`是唯一固定数据来源，符合W02公开视图与本人字段类型；不存其他玩家隐藏底牌、牌序或凭据。`TableScene`只组合展示，`seat-layout.ts`只映射显示位置，不重编号逻辑座位或推算盲注。

`PlayingCard`显示正面及可读牌名，`CardBack`不接收cardId，`CardSlot`表示待发公共牌。本人未参与时不生成手牌。`PlayerSeat`区分真人/电脑、准备/无需准备、离线、房主和位置标记。`ActionBar`仅使用给定合法动作和金额，不实现行动提交。

正式首页复用`ConnectionStatus`，请求真实`/health/live`并保留超时、卸载取消、错误与重试。首页入口处于未开放状态。

## 布局验收

初始公共牌50×70、手牌70×98，五张公共牌固定五槽。2/3/4人分别检查360×640、390×844、430×932、1280×720、1440×900，保存15张牌桌截图；首页/等待各有手机和桌面截图，额外检查长昵称。

移动端主信息及行动区不依靠缩放或横向滚动适配；开发控制放在主内容之后，主要交互至少44×44并有键盘焦点。截图是Chromium视口测试，不代表真实手机、Safari或跨网试玩。

## 生产隔离

App使用`import.meta.env.DEV`条件动态导入开发模块。执行`npm run build`后先运行`npm run verify:preview-bundle`扫描构建文件，再运行`npm run test:production:preview`检查4173生产预览；带开发查询参数仍只显示制作首页。

生产页面仍未配置正式健康代理或同域后端托管，健康失败不代表夹具边界失败。正式部署属于W39。边界验证使用唯一夹具标记，不替代未来服务端身份与权限。

实际检查结果、问题修复与截图见[W04验收](verification/w04.md)。
